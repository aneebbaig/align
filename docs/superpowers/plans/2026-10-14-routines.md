# Routines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Timed daily routines with a tick-off checklist, progress stats, loud scheduled phone notifications, on mobile and web.

**Architecture:** Server owns `Routine` and `RoutineCompletion` (Prisma). One pure module (`src/lib/routines/`) decides what is scheduled on a date and computes the day view and stats; a store + zod schemas back both the `/api/v1/routines` routes and web server actions. The Flutter app reads routines from the API, caches them, and schedules local exact notifications; ticks go through an offline queue.

**Tech Stack:** Next.js 15 / Prisma / zod / Vitest; Flutter (fvm) / Riverpod codegen / Dio / `flutter_local_notifications`, `timezone`, `flutter_timezone`.

**Spec:** `docs/superpowers/specs/2026-10-14-routines-design.md`

## Global Constraints

- Work on branch `dev`; run all Flutter/Dart through `fvm`.
- Leak guard: no tracked file may mention the assistant/vendor name or the user's personal email.
- API responses: `{ "data": ... }` / `{ "error": "..." }`; every route calls `requireBearerAuth` and scopes queries by `userId`; `params` are awaited.
- `time` is `HH:mm` (24h); `days` are ISO weekdays 1-7 (1 = Monday); `date` is `YYYY-MM-DD`; a routine has non-empty `days` XOR a `date`.
- Dates/times use `APP_TIME_ZONE` (`src/lib/day.ts`) on the server.
- Notifications: one high-importance channel `routines`, actions **Done** and **Snooze 10m**; no full-screen intent, no repeat nagging.
- Mirror existing patterns: `src/lib/planner/*`, `src/app/api/v1/tasks/*`, `lib/features/tasks/*`.

## Review Focus

- Routine ticked after midnight for the previous day: delta is large and positive but the day still counts as done.
- Ticking the same routine/day twice (double tap, queue replay): idempotent, keeps the first `completedAt`.
- Un-ticking an item that was never ticked: no error.
- Ticking a routine that is not scheduled on that date: rejected by the API.
- Deleted or deactivated routine: its alarms are cancelled on the next reschedule.
- One-off whose date is in the past: no alarm scheduled.
- Phone timezone differs from `APP_TIMEZONE`: alarms follow the phone clock; the server's day view follows the server timezone (documented limitation).
- Notification Done pressed while app is killed and offline: tick is queued and flushed later.

```ts
export interface RoutineLike { id: string; title: string; time: string; days: number[]; date: string | null; active: boolean }
export interface CompletionLike { routineId: string; date: string; completedAt: Date }
export function addDays(date: string, n: number): string
export function isoWeekday(date: string): number
export function isScheduledOn(r: RoutineLike, date: string): boolean
export interface DayItem { routineId: string; title: string; time: string; done: boolean; completedAt: string | null; deltaMinutes: number | null }
export function dayView(routines: RoutineLike[], completions: CompletionLike[], date: string, timeZone?: string): DayItem[]
export interface DayStat { date: string; scheduled: number; done: number }
export interface Stats { days: DayStat[]; currentStreak: number; bestStreak: number }
export function stats(routines: RoutineLike[], completions: CompletionLike[], from: string, to: string): Stats
```

Rules: `dayView` sorts by `time`; `deltaMinutes = (dayNumber(completedAt,tz) - dayNumber(date))*1440 + localMinutes(completedAt,tz) - minutes(time)`. A day is *complete* if `scheduled > 0 && done === scheduled`; days with `scheduled === 0` are skipped for streaks. `currentStreak` counts consecutive complete days ending at `to`; if `to` itself is scheduled-but-incomplete it is ignored (day in progress) and counting starts at the previous scheduled day. `bestStreak` is the longest run inside the range. Completions for routines not scheduled that date are ignored.

```ts
import { APP_TIME_ZONE, dayNumber } from "@/lib/day";

export function addDays(date: string, n: number): string {
  const [y, m, d] = date.split("-").map(Number);
  return new Date(Date.UTC(y, m - 1, d + n)).toISOString().slice(0, 10);
}
export function isoWeekday(date: string): number {
  const [y, m, d] = date.split("-").map(Number);
  const w = new Date(Date.UTC(y, m - 1, d)).getUTCDay(); // 0 = Sunday
  return w === 0 ? 7 : w;
}
export function isScheduledOn(r: RoutineLike, date: string): boolean {
  if (!r.active) return false;
  return r.days.length > 0 ? r.days.includes(isoWeekday(date)) : r.date === date;
}
const minutes = (t: string) => Number(t.slice(0, 2)) * 60 + Number(t.slice(3, 5));
function localMinutes(d: Date, tz: string): number {
  const parts = new Intl.DateTimeFormat("en-GB", { timeZone: tz, hour: "2-digit", minute: "2-digit", hourCycle: "h23" }).formatToParts(d);
  const n = (t: string) => Number(parts.find((p) => p.type === t)?.value);
  return n("hour") * 60 + n("minute");
}
function dateNumber(date: string): number {
  const [y, m, d] = date.split("-").map(Number);
  return Date.UTC(y, m - 1, d) / 86_400_000;
}
```
`dayView`: filter scheduled, map to item using a `Map` keyed `routineId|date`. `stats`: loop `from..to` with `addDays`, build `DayStat`s, then compute streaks per the rules above.

```ts
const time = z.string().regex(/^([01]\d|2[0-3]):[0-5]\d$/, "Time must be HH:mm");
```
